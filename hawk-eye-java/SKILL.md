# Hawk Eye Java Review Skill

## 何时使用

当你需要评审 Java 后端代码时使用：
- 分层不清、业务逻辑混杂。
- 事务边界和异常处理不明确。
- 并发安全或性能风险。

## 输入

至少提供以下之一：
- Controller/Service/Repository 代码或代码片段。
- 一条接口调用链描述。
- 已知 Bug 现象和日志片段。

## 执行步骤

1. 识别结构
- 定位接口层、服务层、持久层、公共组件。

2. 重点检查
- 代码是否符合项目的编码规范。
- 分层依赖方向是否正确。
- 事务范围和异常传播是否合理。
- 线程安全和共享对象风险。
- SQL 与 IO 调用的性能风险。
- 日志与可观测性是否足够。

3. 评分规则（低分优先）
- 出现一个P0级别问题（编译或语法问题）：【0-1分】
- 出现一个P1级别问题（极其严重的问题，可能导致系统崩溃或数据完全丢失）：【2-3分】
- 出现一个P2级别问题（存在非常容易忽视的隐藏风险）：【4-6分】
- 出现一个P3级别问题（影响系统性能或可维护性的问题）：【7-8分】
- 出现一个P4级别问题（代码风格或规范性问题）：【9分】
- 出现一个P5级别问题（无明显问题，几乎完美，代码质量很高）：【10分】

4. 输出问题
- 汇总问题，按照**严重级别由高到低**顺序输出问题。
- 问题点对应的**行号**尽量准确。
- 标明**影响范围**、**触发条件**。
- 建议的修复方案或优化措施。
- 如果是分析错误信息时，给出问题的根本原因分析。

5. 生成报告
- 按 `templates/review-template.md` 输出。

## 输出要求
- 评分（所有问题汇总后按评分规则打分）
- 总体结论
- Top 问题列表（按严重级别由高到低）。
- 每个问题对应修复建议和示例代码。
- 可执行任务清单。

## 快速调用示例
